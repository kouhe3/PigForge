# Intent: 弹簧与拳套的原版化（G62 / G95）

> 2026-10-04 用户提出并拍板：①弹簧「越弹越高」要修（范围 = 拆键 + 原版关节 + 探针验收，一次做完）；②拳套在原版是可交互零件、现在完全不可交互，走 **A：立「一个放置件 → N 运行时实体」机制 + 做完整原版拳套**。

- **Outcome:** 弹簧不再是「接触即给自己向上冲量」的弹跳垫，而是原版那条**可断的软关节**（弹力绳 250 N/m / 20 N·s/m，或 y 限位 0.1 m；拉过 3 m 断并由端点刚体续接），**永远不会无中生有地给车加能量、也不会把自己的焊缝扯断**；拳套恢复原版的可交互伸缩拳套（第二刚体「手套」，触摸/开关触发，出拳并打断身后相邻件的关节，1 s 后回卷）。
- **User:** 仓库维护者本人 + 甲方试玩（弹簧/拳套都在建造栏里能直接拿到）。
- **Why now:** 甲方在实机试玩里报了「弹簧越弹越高」；拳套是同一批内容里唯一「原版可交互、我们完全没做」的零件，而它与沙袋/气球的多刚体需求是同一堵墙，早定早解锁。
- **Success:** 弹簧 + 木框的车从坡上下来**不被自己的弹簧撕开、不自己弹起**；用弹簧把两件连起来能感觉到「拉得住、会回弹」；拳套点一下/碰一下能**打出去**并把手套后面那件打脱，1 s 后回卷，能再打；`dotnet test` / `pnpm test` / `pnpm build` 全绿。
- **Constraint:** 权威只在服务器；不改 PGFS/PGFC 布局（手套是**第二个实体**，走既有 73 B 记录，不加字段/不加帧）；不改 `--play` 语义；内容值一律由 `tools/bple-springs` 提取（禁止手写原版定义过的数）；`content/parts.json` 同一时刻只有一个写者。
- **Spec:** `docs/specs/spring-joint.md`（弹簧）、`docs/specs/boxing-glove.md`（拳套 + 运行时子实体）、`docs/decisions/ADR-027-runtime-sub-entities.md`（机制决策）。
- **Out of scope:** 绳（G63）、多刚体沙袋/气球本身（G52/G53，机制做好后另开）、弹簧/拳套的**视觉**（弹簧线随锚点拉伸、手套伸出动画）——另记 P1 客户端项；IN 开关面的完整配置（只取与本切片相关的三个键）。
